# 云膳外卖平台技术架构文档

## 1. 项目目标

云膳外卖是一套用于求职展示与工程实践的餐饮点餐、交易和履约系统。第一版采用模块化单体架构，重点覆盖认证授权、缓存、并发库存、订单幂等、异步消息、实时通知、容器化部署与多端开发。

## 2. 系统组成

| 子系统 | 技术 | 职责 |
|---|---|---|
| 用户端 | uni-app、Vue 3、TypeScript、Pinia | 微信小程序点餐、购物车、下单与订单查询 |
| 商家端 | Vue 3、TypeScript、Element Plus、Pinia | 菜品、订单与经营数据管理 |
| 服务端 | Java 17、Spring Boot 3.5、Spring Security、MyBatis-Plus | 业务规则、认证授权和数据访问 |
| 数据设施 | MySQL 8、Redis 7、RabbitMQ 4 | 持久化、缓存与异步消息 |
| 工程设施 | Flyway、Docker Compose、Actuator、GitHub Actions | 数据迁移、部署、监控入口与持续集成 |

## 3. 后端模块

后端按业务包组织：

- `auth`：管理员认证、JWT 签发与解析。
- `user`：用户演示登录和地址。
- `product`：分类、菜品、库存与缓存。
- `cart`：用户购物车。
- `order`：订单创建、状态机、支付与超时关闭。
- `notification`：WebSocket 实时通知。
- `statistics`：经营数据聚合。
- `common`：响应结构、异常和用户上下文。

模块化单体避免了个人项目过早引入服务发现、分布式事务和多仓库运维，同时保留清晰边界，后续可以独立拆分订单或支付模块。

## 4. 核心业务流程

### 4.1 下单

1. 从 JWT 获取当前用户，禁止客户端传入用户 ID。
2. 通过 `user_id + client_order_no` 查询是否存在订单；重复请求直接返回原订单。
3. 校验地址归属，防止越权使用他人地址。
4. 从数据库重新读取菜品状态和价格，客户端购物车价格不作为结算依据。
5. 使用 `UPDATE ... SET stock=stock-? WHERE stock>=?` 原子扣减库存。
6. 在同一数据库事务内保存订单及明细并清理购物车。
7. 发送 RabbitMQ 延迟消息，15分钟后检查是否仍待支付。

数据库唯一索引 `uk_user_client_order(user_id, client_order_no)` 是幂等的最终兜底。

### 4.2 支付

第一版提供模拟支付，便于没有微信商户号时完整演示业务流程。支付更新使用带原状态的条件 SQL，仅允许 `PENDING_PAYMENT/UNPAID` 更新为已支付和待接单，重复调用不会重复改变订单。

接入真实微信支付时，应保留相同的领域入口，并新增签名验证、支付流水、回调原文留存和退款流水。订单是否支付必须以服务端验签后的回调为准。

### 4.3 超时关单

订单 ID 进入带 TTL 的 RabbitMQ 队列，过期后经死信交换机进入关闭队列。消费者使用条件更新，只关闭仍为待付款的订单；成功关闭后根据订单明细回补库存。重复消息不会重复回补。

### 4.4 状态机

合法主链路：

`待付款 → 待接单 → 制作中 → 待配送 → 配送中 → 已完成`

待付款和待接单可以进入已取消。终态不能继续流转。服务层规则与数据库条件更新共同防止并发状态覆盖。

## 5. 安全设计

- Spring Security 使用无状态会话，接口通过 JWT 认证。
- 管理端接口要求 `ADMIN` 角色；用户接口要求已登录。
- 密码使用 BCrypt，不保存明文。
- 地址、购物车和订单始终从当前登录用户派生。
- 全局异常不会把数据库堆栈返回客户端。
- 生产环境必须更换 JWT、MySQL、RabbitMQ 和 MinIO 凭据并启用 HTTPS。

当前 WebSocket 用于本地作品演示，生产扩展时应在握手阶段校验一次性连接票据，并通过 Redis Pub/Sub 或消息代理支持多实例广播。

## 6. 缓存设计

分类和在售菜品使用 Spring Cache + Redis：

- 查询：先缓存，未命中查数据库并写入缓存。
- 写入：数据库事务完成后清除菜品缓存。
- Key 按分类隔离，避免无关数据互相覆盖。

后续应增加随机过期时间、空值缓存和热点缓存重建保护，并记录命中率。

## 7. 数据库关键索引

- `orders(user_id, status, created_time)`：用户按状态查询订单。
- `orders(status, created_time)`：商家处理订单。
- `orders(order_number)`：订单号唯一定位。
- `orders(user_id, client_order_no)`：下单幂等。
- `dish(category_id, status)`：分类查询在售菜品。
- `shopping_cart(user_id, dish_id)`：购物项唯一与快速查询。

金额使用 `DECIMAL(10,2)` 和 Java `BigDecimal`，不使用浮点类型。

## 8. 可观测性

Actuator 暴露 `health`、`info`、`metrics` 和 `prometheus` 端点。后续接入 Prometheus/Grafana 后，应重点监控请求 P95、错误率、JVM、连接池、Redis 和 RabbitMQ 积压。

## 9. 已知边界

- 第一版为单门店模型。
- 支付为明确标注的模拟实现。
- 图片字段已保留，MinIO 上传接口将在下一阶段补充。
- 用户端地址第一版提供种子地址读取，完整增删改在下一阶段补充。
- 暂未接入配送员子系统、优惠券、评价和真实微信登录。
