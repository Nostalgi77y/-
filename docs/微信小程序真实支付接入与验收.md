# 云膳外卖：微信小程序真实支付接入与验收

## 1. 本版已完成的支付链路

1. 小程序调用 `uni.login` 获取一次性 `code`。
2. 服务端调用微信 `jscode2session`，取得真实 `openid`，创建或匹配云膳用户并签发 JWT。
3. 用户提交订单后可立即付款，未付款订单也可从“订单”页再次付款。
4. 服务端使用微信支付 API v3 小程序支付接口统一下单，只向小程序返回调起收银台所需参数。
5. 小程序调用 `uni.requestPayment` 调起微信收银台。
6. 前端返回成功后服务端主动向微信查单，微信也会向公网回调地址推送结果。
7. 服务端验签、解密通知，并校验 AppID、商户号、订单号和金额；只有微信交易状态为 `SUCCESS` 才把订单改为已支付。
8. 数据库保存支付渠道、微信交易号和预支付号，状态条件更新保证重复通知不会重复入账。
9. 微信支付有效期早于本地 15 分钟关单时间；超时任务会先向微信查单或关单，再取消本地订单，避免扣款与订单取消冲突。

> 前端的“支付成功”回调不能作为入账依据。本项目最终以微信查单或通过验签的支付通知为准。

## 2. 你需要准备的资料

- 已认证、可发布的微信小程序及 AppID、AppSecret。
- 已开通 JSAPI/小程序支付权限的微信支付商户号，且商户号已与该 AppID 绑定。
- 商户 API 证书序列号、对应的商户 API 私钥文件 `apiclient_key.pem`。
- 32 字节 API v3 密钥。
- 已备案的 HTTPS 后端域名。回调必须可由微信支付公网访问，不能使用本机或局域网地址。

私钥、AppSecret 和 API v3 密钥严禁提交到 Git。生产环境应使用服务器密钥管理或只读 Docker Secret。

## 3. 配置步骤

### 3.1 微信公众平台

1. 取得 AppID 和 AppSecret。
2. 将后端正式域名加入 `request` 合法域名，必须使用 HTTPS。
3. 在 `cloud-meal-user/src/manifest.json` 的 `mp-weixin.appid` 中填写同一个 AppID。
4. 微信开发者工具导入 `cloud-meal-user/dist/build/mp-weixin`。

### 3.2 微信支付商户平台

1. 绑定本小程序 AppID，确认 JSAPI/小程序支付产品已开通。
2. 设置 API v3 密钥。
3. 下载商户 API 证书，记录证书序列号并安全保存私钥。

### 3.3 服务端环境变量

复制仓库根目录 `.env.example` 的变量到实际部署环境：

```text
PAYMENT_MODE=WECHAT
WECHAT_APP_ID=wx...
WECHAT_APP_SECRET=...
WECHAT_PAY_MERCHANT_ID=190...
WECHAT_PAY_MERCHANT_SERIAL_NUMBER=...
WECHAT_PAY_API_V3_KEY=32字节密钥
WECHAT_PAY_PRIVATE_KEY_PATH=/run/secrets/apiclient_key.pem
WECHAT_PAY_NOTIFY_URL=https://你的后端域名/api/payment/wechat/notify
```

Docker 部署时，把私钥以只读方式挂载到容器，使 `WECHAT_PAY_PRIVATE_KEY_PATH` 指向容器内路径：

```yaml
services:
  server:
    env_file: ../.env
    volumes:
      - C:/secure/wechat/apiclient_key.pem:/run/secrets/apiclient_key.pem:ro
```

不要把实际 `.env` 或私钥放进项目目录。

## 4. 本地与真实模式

- `PAYMENT_MODE=MOCK`（默认）：用于本地开发。统一支付接口会把订单标为已付款，但不会扣钱，页面提示“本地支付成功”。
- `PAYMENT_MODE=WECHAT`：开启真实微信支付。服务启动时会检查商户参数，缺少关键参数会拒绝启动。
- 全额优惠订单金额为 0 时不调用微信，支付渠道记录为 `COUPON`。

切换模式或修改商户参数后必须重启服务端。

## 5. 真机验收清单

1. 将测试商品价格设为 `0.01` 元，使用真机测试。
2. 清除小程序缓存并重新登录，数据库 `user.openid` 不应为 `demo-openid`。
3. 下单并付款，确认微信账单真实产生交易。
4. 检查订单：`pay_status=PAID`、`payment_channel=WECHAT`、`transaction_id` 与 `payment_time` 有值、状态为 `PENDING_ACCEPTANCE`。
5. 在商户平台用订单号核对金额和交易状态。
6. 重放同一回调，订单状态和营收不得重复变化。
7. 付款后立即关闭小程序，再进入订单页仍应显示已付款，以验证回调链路。
8. 回调失败时检查 HTTPS 证书、反向代理是否保留 `Wechatpay-*` 请求头及后端日志。

## 6. 接口一览

| 接口 | 鉴权 | 用途 |
| --- | --- | --- |
| `POST /api/user/auth/wechat-login` | 否 | 微信 code 换取云膳登录令牌 |
| `POST /api/user/orders/{id}/payment` | 用户 JWT | 统一下单并取得支付参数 |
| `POST /api/user/orders/{id}/payment/confirm` | 用户 JWT | 前端返回成功后由服务端向微信查单 |
| `POST /api/payment/wechat/notify` | 微信签名 | 微信异步通知；服务端验签解密 |
