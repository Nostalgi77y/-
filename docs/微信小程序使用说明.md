# 微信小程序使用说明

## 当前完成情况

第一版用户端已经使用 uni-app、Vue 3、TypeScript 和 Pinia 完成，并能编译为微信小程序。已实现分类与菜品、演示登录、购物车、默认地址读取、下单、模拟支付和订单列表。

当前属于本地求职演示版本：微信 AppID、微信授权登录、微信商户支付和正式 HTTPS 域名尚未接入。

## 导入微信开发者工具

1. 确保 Docker 完整环境已经启动，后端健康地址为 `http://localhost:8080/api/actuator/health`。
2. 在项目根目录执行：

   ```powershell
   cd cloud-meal-user
   npm install
   npm run build:mp-weixin
   ```

3. 打开微信开发者工具，选择“导入项目”。
4. 项目目录选择 `cloud-meal-user/dist/build/mp-weixin`。
5. 本地演示可选择测试号或“不使用 AppID”；正式开发填写自己的小程序 AppID。
6. 在“详情 → 本地设置”中勾选“不校验合法域名、web-view、TLS版本以及HTTPS证书”。该选项只用于本地开发。
7. 点击编译。菜品加入购物车时会自动完成演示用户登录。

## 本地演示流程

1. 点餐页选择分类和菜品。
2. 点击 `+` 加入购物车。
3. 购物车提交订单，系统使用种子数据中的默认地址。
4. 弹窗选择模拟支付。
5. 商家管理端 `http://localhost` 接收并处理订单。
6. 回到小程序订单页查看状态。

## 真机调试

手机中的 `localhost` 指向手机自身，不能访问电脑后端。真机调试有两种方式：

- 临时调试：把 `VITE_API_BASE_URL` 设置为电脑局域网地址，例如 `http://192.168.1.10:8080/api`，确保手机与电脑同一网络且防火墙允许8080端口。
- 正式方案：部署后端到服务器，配置备案 HTTPS 域名，并在微信公众平台加入“request合法域名”。

正式接口地址通过 `.env.production` 配置：

```env
VITE_API_BASE_URL=https://你的域名/api
```

## 接入真实微信登录

当前 `/user/auth/demo-login` 固定使用演示用户。正式登录需要：

1. 小程序调用 `uni.login()` 获取一次性 `code`。
2. 把 `code` 发送给 Spring Boot。
3. 服务端携带 AppID 和 AppSecret 调用微信 `code2Session`。
4. 根据 `openid` 查询或创建用户。

## 收货地址与优惠券

- 在“我的”页面进入“收货地址”，可以新增、编辑、删除及设置默认地址。
- 在“我的”页面进入“优惠券”，可领取活动券；已领取的券会显示为“已领取”。
- 购物车结算时必须选择收货地址，并可从满足门槛的未使用优惠券中选择一张。
- 下单金额由后端重新计算，前端只提交地址 ID 和用户优惠券 ID，防止篡改优惠金额。
- 测试数据包含“满 20 减 5”和“满 50 减 10”优惠券。
5. 服务端签发本系统 JWT，客户端保存并用于后续请求。

AppSecret 只能保存于服务端环境变量，不能写入小程序源码。

## 接入真实微信支付

当前支付接口为 `mock-pay`。正式支付需要：

1. 服务端创建业务订单并调用微信支付下单接口。
2. 服务端把小程序调起支付所需参数返回用户端。
3. 用户端调用 `uni.requestPayment()`。
4. 微信支付平台异步通知服务端。
5. 服务端验签、核对金额和商户号，通过条件更新保证回调幂等。

订单最终支付状态必须以服务端验签后的微信回调为准，不能相信客户端支付结果。
