# 后续添加与完善计划

## P0：上线前必须完成

1. 接入真实微信登录：服务端使用 `code` 换取 `openid`，AppSecret 只保存在服务端。
2. 接入真实微信支付：支付预下单、签名、回调验签、支付流水、退款和对账。
3. 完整地址增删改、手机号授权与隐私协议。
4. MinIO/OSS 图片上传、类型校验、大小限制和旧文件回收。
5. WebSocket 握手票据认证；多实例使用 Redis Pub/Sub 或 RabbitMQ 广播。
6. 更换所有默认密码和 JWT 密钥，启用 HTTPS、CORS 白名单及生产日志脱敏。
7. 增加完整集成测试与接口回归，订单/库存/支付模块覆盖率优先达到80%。

## P1：增强求职技术亮点

1. Redis Lua 一次性下单令牌与注解式接口限流。
2. RabbitMQ Publisher Confirm、Return、消费者手动确认、重试与死信告警。
3. 本地消息表/Outbox，解决数据库提交与消息发送一致性问题。
4. Testcontainers 启动 MySQL、Redis 和 RabbitMQ 进行集成测试。
5. k6/JMeter 压测，保存优化前后平均响应、P95、P99 和吞吐量。
6. Prometheus、Grafana、Loki，建立接口错误率、慢请求和队列积压告警。
7. GitHub/Gitee CI：测试、构建镜像、漏洞扫描和测试环境部署。
8. 增加审计日志、Trace ID、慢 SQL 与管理端操作记录。

## P2：业务能力

- 多门店与门店距离。
- 套餐、菜品口味和规格库存。
- 优惠券、满减、会员积分。
- 收藏、评价、售后退款。
- 配送员端和配送轨迹。
- 商家营业时间与预约单。
- 销量排行、用户留存、订单趋势和 Excel 报表。

## 微服务演进条件

只有在单体业务闭环、测试和监控稳定后再考虑拆分。优先拆分边界为商品、交易订单、支付和通知。拆分前先解决：

- 服务间认证与配置管理。
- 分布式链路追踪。
- 幂等与消息最终一致性。
- 数据库归属与跨服务查询。
- 灰度发布、熔断、降级和限流。

不建议仅为了简历名称而引入 Spring Cloud；应以真实压力、团队边界或独立伸缩需求作为拆分依据。
